# 休养期间工作计时提醒期 — 开发方案 v0.1

> 状态：已审核通过（2026-10-19）。确认项：GitHub 公开仓库、工作/休息本地记录、GUI 设置工作时长与提醒。
> 日期：2026-10-19
> 版本：v0.2（审核后修订）
> 目标平台：Windows 10/11 x64（当前机器为 Windows 11，版本 10.0.26200）
> 工作目录：`C:\Temp\rest-work-timer`

---

## 1. 方案摘要

做一个**本机运行的 Windows 托盘小工具**，用“工作—休息”状态机管理休养期间的单次工作时长：

- 每次真正开始工作（登录/解锁后首次键鼠操作、从睡眠恢复后首次操作）启动 **30:00 倒计时**。
- 剩余 **60 秒**（29:00）和 **30 秒**（29:30）各提醒一次，带声音和非抢焦点弹窗。
- 倒计时归零 → 立即 `LockWorkStation()` 锁屏，进入 **Rest（休息）** 状态。
- Rest 期间**不结束、不暂停任何自动化程序**，并阻止系统因空闲而睡眠，保证后台自动化继续跑。
- 解锁屏幕后弹出休息确认框：必须手动点“结束休息，开始新的工作周期”才解除；选择“继续休息”则 15 秒后重新锁屏。
- 工作过程中如果系统因空闲自动锁屏/睡眠/休眠，倒计时**清零**；下次解锁并产生真实键鼠操作时重新从 30:00 开始。
- 用低级键鼠钩子识别输入，并过滤 `LLKHF_INJECTED` / `LLMHF_INJECTED`，**自动化脚本模拟的键鼠不算工作**。
- 本地优先：配置、日志、工作/休息记录只存本机；GitHub 只用于开发管理（公开仓库、Issue、里程碑、PR、CI），运行数据不上传。

**技术选型：C# / .NET 8 + WinForms 托盘程序。** 不装驱动、不要管理员权限、不写系统服务；当前机器已有 .NET 8 Desktop Runtime，只需在项目内临时安装 .NET 8 SDK 用于编译。选择 WinForms 是因为托盘、低级钩子、电源/会话消息、锁屏、防休眠这些 Win32 能力用 C# 实现最直接，生成单个 exe，后续维护成本低。

## 2. 需求拆解与验收标准

| 编号 | 需求 | 实现口径 | 验收标准 |
|---|---|---|---|
| R1 | 每次开始工作都启动倒计时 | 登录后首次真实键鼠、解锁后首次真实键鼠、睡眠/休眠恢复后首次真实键鼠，均从完整时长开始 | 冷启动登录后敲一下键盘，托盘显示 `30:00` 并开始走秒 |
| R2 | 默认 30 分钟，可配置 | 设置项 1–180 分钟；默认 30 | 改成 2 分钟后保存，下个周期按 2 分钟运行 |
| R3 | 提前 60 秒、30 秒提醒 | 在剩余 60s 和 30s 各触发一次，单周期内不重复 | 29:00、29:30 各出现一次提示和声音；不早不晚、不重复 |
| R4 | 归零进入休息并锁屏 | 归零即调用系统锁屏；状态切到 Rest | 倒计时到 0，工作站立即锁定；托盘仍运行 |
| R5 | 休息时自动化继续运行 | 不杀进程、不挂起进程；Rest 期间用 `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)` 阻止系统睡眠 | 锁屏后自动化进程 PID 不变、继续写日志；`powercfg /requests` 能看到本程序的 SYSTEM 请求 |
| R6 | 手动解除休息 | 解锁后弹确认框；必须点“结束休息”才进入新的工作周期；不操作则重新锁屏 | 解锁后出现确认框；选“继续休息”15 秒内重新锁屏；选“结束休息”立即开始新的 30:00 |
| R7 | 长时间无操作导致锁屏/睡眠则清零 | 监听系统会话锁屏和电源挂起事件；非本程序发起的锁屏/睡眠把状态重置为 Idle | 工作到 10:00 时手动锁屏，解锁后不自动走秒；敲键盘后从 30:00 重新开始 |
| R8 | 排除自动化输入 | 低级钩子过滤 injected 标志；不记录键值，只记录“发生过真人输入” | 用 PowerShell `SendInput` 连续模拟输入，倒计时不启动；真人按键立即启动 |
| R9 | 开机自启、单实例、可配置 | HKCU Run 自启；命名互斥体保证单实例；JSON 配置 | 重启后托盘自动出现；重复启动只弹已有实例；配置重启后保留 |
| R10 | 连接 GitHub 做开发管理 | 用 GitHub CLI 设备码登录；建公开仓库；Issue/里程碑/PR/CI 同步开发进度 | 仓库可公开访问、CI 通过、每个功能有对应 Issue/PR、提交已推送 |

### 名词口径

- **“开机启动”**：指用户登录 Windows 后启动，而不是 BIOS/内核启动阶段。锁屏界面下没有“工作”，不启动倒计时。
- **“工作开始”**：会话处于解锁状态，且出现一次**非注入**的键盘/鼠标输入。仅解锁但不操作，不算开始。
- **“休息”**：倒计时归零后的锁定状态，时长不固定，直到用户手动解除。
- **“自动化”**：通过 `SendInput`、AutoHotkey、PyAutoGUI 等注入方式产生的键鼠事件；不包含远程桌面里的人为操作。

## 3. 状态机与行为规则

### 3.1 状态

```
                真人键鼠 / 登录后首次输入
        ┌──────────────────────────────────┐
        │                                  ▼
   ┌─────────┐                          ┌─────────┐
   │  Idle   │                          │ Working │
   │ 倒计时0 │                          │ 30:00→0 │
   └─────────┘                          └─────────┘
        ▲                                  │
        │ 系统锁屏 / 睡眠 / 休眠            │ 归零
        │ （非本程序发起）                   ▼
        │                              ┌─────────┐
        └──────────────────────────────│  Rest   │
                                       │ 锁屏+防睡│
                                       └─────────┘
                                            │
                              解锁 + 点击“结束休息”
                                            │
                                            ▼
                                       Working（新的 30:00）
```

### 3.2 事件与迁移

| 事件 | 当前状态 | 动作 | 新状态 |
|---|---|---|---|
| 程序启动（已登录且已解锁） | — | 不立即走秒，等待首次真人输入 | Idle |
| 程序启动（锁屏界面） | — | 等待解锁 | Idle |
| 真人键鼠 | Idle | 启动完整倒计时 | Working |
| 真人键鼠 | Working | 只更新“最后真人输入时间”，**不重置**倒计时 | Working |
| 系统锁屏（非 Rest 触发） | Working | 取消计时、清提醒标记、倒计时归零 | Idle |
| 系统解锁 | Idle | 等待首次真人输入 | Idle |
| 系统睡眠/休眠（挂起） | Working | 取消计时、归零 | Idle |
| 系统恢复 | Idle | 等待首次真人输入 | Idle |
| 剩余 60s | Working | 提醒一次（声音 + 弹窗） | Working |
| 剩余 30s | Working | 提醒一次（声音 + 弹窗） | Working |
| 剩余 0s | Working | 置 `selfLock=true`，调用系统锁屏，开启防休眠 | Rest |
| 系统锁屏事件，且 `selfLock=true` | Rest | 忽略（不能把自己的锁屏当成“离开”） | Rest |
| 解锁 | Rest | 弹出休息确认框；15 秒无操作重新锁屏 | Rest |
| 点击“结束休息” | Rest | 关闭防休眠、清 `selfLock`、启动新的完整倒计时 | Working |
| 点击“继续休息” | Rest | 立即重新锁屏 | Rest |
| 程序退出（Rest 中） | Rest | 二次确认；退出会解除防休眠，但不会解锁屏幕 | 退出 |

### 3.3 计时规则

- 用单调计时（`Stopwatch` / `Environment.TickCount64`）计算剩余时间，避免系统时间被修改导致跳变。
- UI 每 250ms 刷新一次，提醒判定按剩余秒数取整，使用 `warned60` / `warned30` 布尔标记保证单周期只触发一次。
- 倒计时只在 `Working` 状态推进；`Idle` 显示 `--:--`，`Rest` 显示“休息中”。
- 锁屏/睡眠会把整个周期作废，而不是暂停后继续。这是需求 R7 的明确要求。

### 3.4 “手动解除”的判定

系统锁屏后，程序无法在安全桌面上显示任何 UI，所以“手动解除”只能发生在**用户解锁之后**：

1. 用户解锁 → 程序收到 `WTS_SESSION_UNLOCK`。
2. 程序弹出置顶确认框（不抢焦点、不覆盖密码框）：
   - **结束休息，开始新的工作周期** → 解除 Rest，立即从完整时长开始。
   - **继续休息（重新锁屏）** → 15 秒后再次锁屏。
3. 若用户直接关闭确认框或不做选择，15 秒后自动重新锁屏，防止“解锁即等于解除”。

> 如果你希望“解锁即自动解除”，这是一行配置的差别；默认采用更严格的“解锁后还需确认”，避免误解除。

### 3.5 自动化与锁屏的冲突（重要）

“锁屏”和“GUI 自动化继续运行”在 Windows 上存在天然冲突：

- 后台进程、网络任务、文件处理、数据库任务：锁屏后继续运行，没有问题。
- 依赖桌面窗口、`SendInput`、UI Automation、浏览器点击的自动化：Windows 切到安全桌面后，这类操作通常会被阻断或失效。

因此方案提供两种 Rest 呈现模式，默认第一种：

| 模式 | 行为 | 适用 |
|---|---|---|
| `lock`（默认） | 真正锁屏，防休眠；GUI 自动化可能停摆 | 自动化是后台/服务型任务 |
| `overlay` | 不锁系统，只显示全屏置顶遮罩，键鼠被遮罩挡住；桌面仍解锁，GUI 自动化可继续 | 自动化必须操作桌面窗口（v0.1 暂不实现，仅保留设计） |

如果你的自动化属于第二种，需要明确告知；否则默认按 `lock` 实现，并在文档中写清限制。

## 4. 技术架构

### 4.1 进程与模块

单进程、单实例、x64、WinForms，无管理员权限、无驱动、无 Windows 服务。

```
RestWorkTimer.exe
├─ AppShell            程序入口、单实例互斥、异常兜底、开机自启
├─ MainForm            主窗口：大字倒计时、状态、开始/重置/立即休息、设置与历史入口
├─ SettingsForm        设置：工作分钟、60s/30s 提醒开关、自启、声音、休息模式
├─ HistoryForm         本地工作/休息记录查看、筛选、导出 CSV
├─ TrayUI              托盘图标、菜单、状态/剩余时间
├─ TimerEngine         状态机、倒计时、提醒去重（纯逻辑，可单测）
├─ InputMonitor        WH_KEYBOARD_LL / WH_MOUSE_LL，过滤 injected
├─ SessionPowerMonitor WTS 会话锁屏/解锁、WM_POWERBROADCAST 睡眠/恢复
├─ RestController      LockWorkStation、防休眠、休息确认框
├─ NotificationService 非抢焦点弹窗 + 声音
├─ ConfigStore         JSON 配置、原子写入、默认值/校验
├─ SessionStore        本地工作/休息记录（JSONL、追加写、按天/按大小滚动）
└─ Logging             JSONL 本地日志、按天滚动、脱敏
```

### 4.2 关键 Win32 / .NET API

| 能力 | 实现 |
|---|---|
| 全局键鼠 | `SetWindowsHookEx(WH_KEYBOARD_LL/WH_MOUSE_LL)`；检查 `KBDLLHOOKSTRUCT.flags` 的 `LLKHF_INJECTED`/`LLKHF_LOWER_IL_INJECTED`，`MSLLHOOKSTRUCT.flags` 的 `LLMHF_INJECTED`/`LLMHF_LOWER_IL_INJECTED` |
| 锁屏 | `user32.dll!LockWorkStation()` |
| 防休眠 | `kernel32.dll!SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)`；解除时 `ES_CONTINUOUS` |
| 会话锁屏/解锁 | `wtsapi32.dll!WTSRegisterSessionNotification` + `WM_WTSSESSION_CHANGE`（`WTS_SESSION_LOCK` / `WTS_SESSION_UNLOCK`） |
| 睡眠/恢复 | 隐藏消息窗口接收 `WM_POWERBROADCAST`：`PBT_APMSUSPEND`、`PBT_APMRESUMEAUTOMATIC`、`PBT_APMRESUMESUSPEND` |
| 托盘 | `System.Windows.Forms.NotifyIcon` |
| 通知 | 自绘无边框 `TopMost` 小窗，`ShowWithoutActivation`，`SystemSounds` / `PlaySound` |
| 自启 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值为 `"<exe>" --autostart` |
| 单实例 | `Mutex("Local\\RestWorkTimer.SingleInstance")` |
| 配置保护 | GitHub token 用 `ProtectedData.Protect(CurrentUser)`；MVP 不需要 token |
| 日志 | `%LOCALAPPDATA%\RestWorkTimer\logs\app-YYYYMMDD.jsonl` |

### 4.3 数据与配置

配置路径：`%APPDATA%\RestWorkTimer\config.json`

```json
{
  "schemaVersion": 1,
  "workMinutes": 30,
  "warnSeconds": [60, 30],
  "idleResetMinutes": 0,
  "lockOnRest": true,
  "keepAwakeDuringRest": true,
  "restMode": "lock",
  "restReleaseRequiresConfirm": true,
  "autoStart": true,
  "soundEnabled": true,
  "popupEnabled": true,
  "localRecords": true,
  "historyRetentionDays": 180
}
```

- `idleResetMinutes = 0`：不按“多久没输入”自行清零，只在系统真的锁屏/睡眠时清零。若要更保守，可改成 10 分钟；但那样用户静坐思考 10 分钟也会被清零，默认不启用。
- 状态不跨进程持久化：程序重启/崩溃后回到 Idle，绝不因为“上次在 Rest”而擅自锁屏。
- 配置写入采用临时文件 + 替换，避免断电写坏。

### 4.4 本地工作/休息记录

路径：`%APPDATA%\RestWorkTimer\sessions.jsonl`，一行一条，追加写；默认保留 180 天，启动时清理过期文件。

```json
{"id":"...","startedAt":"2026-10-19T12:00:00+08:00","endedAt":"2026-10-19T12:30:00+08:00","plannedMinutes":30,"workedSeconds":1800,"endReason":"rest","restStartedAt":"2026-10-19T12:30:00+08:00","restEndedAt":"2026-10-19T12:43:12+08:00","restSeconds":792}
```

- `endReason`：`rest`（正常休息）、`lock`（系统锁屏清零）、`sleep`（睡眠清零）、`manualReset`（手动重置）、`exit`（退出）。
- 只记录时间、时长、结束原因；**不记录键值、窗口标题、进程名、屏幕内容**。
- 历史窗口支持按日期筛选、查看汇总（总工作分钟/休息次数/平均周期）、导出 CSV。
- JSONL 追加写 + 定期压缩/滚动；写入失败只记日志，不影响计时和锁屏主流程。

### 4.5 构建与分发

- 项目内用官方 `dotnet-install.ps1` 安装 .NET 8 SDK 到 `.dotnet/`（不污染全局，不需要管理员）。
- `dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true`，生成单文件 `RestWorkTimer.exe`，依赖已安装的 .NET 8 Desktop Runtime。
- 另提供 self-contained 发布脚本（约 80–100MB），用于换机或无运行时环境。
- GitHub Actions：`windows-latest` + `setup-dotnet 8.0.x`，执行 `dotnet build`、`dotnet test`、`dotnet publish`，上传 artifact。
- 不引入第三方 UI 框架；NuGet 仅测试项目使用 xUnit。

### 4.6 隐私与安全

- 键鼠钩子**只记录事件发生时间**，不记录键值、不记录窗口标题、不截屏、不记录剪贴板。
- 工作/休息记录、运行日志只存本机，不自动上传 GitHub。
- 不修改系统锁屏策略、不关闭杀毒、不注入其他进程。
- 需要用户交互的只有：首次设置、GitHub 授权（仅开发期）、休息解除确认。

## 5. UI / UX

### 5.1 托盘

- 图标三态：灰色 Idle、绿色 Working、橙色 Rest。
- Tooltip：`工作中 12:34` / `休息中（已锁屏）` / `待开始`。
- 右键菜单：
  - `状态：工作中 12:34`（只读）
  - `重置计时`（重新从完整时长开始）
  - `立即休息`（测试/主动休息，二次确认）
  - `设置…`
  - `查看日志`
  - `退出`
- 双击托盘：打开主窗口（不抢焦点）。

### 5.2 提醒

- 60 秒：`还有 1 分钟，准备收尾。`
- 30 秒：`还有 30 秒，即将锁屏休息。`
- 右下角非激活弹窗，8 秒自动消失；同时播放提示音。
- 弹窗不抢当前窗口焦点，不打断全屏会议/视频；若全屏应用屏蔽弹窗，声音仍然有效。
- 可在设置中关闭声音或弹窗，但默认都开。

### 5.3 休息确认框

```
┌────────────────────────────────────┐
│  休息中 · 自动化仍在运行            │
│                                    │
│  本次工作已完成 30:00。             │
│  系统将在 15 秒后重新锁屏。         │
│                                    │
│  [ 结束休息，开始新的工作周期 ]     │
│  [ 继续休息（立即锁屏） ]           │
└────────────────────────────────────┘
```

- 置顶、居中、不显示密码输入框。
- 键盘：`Enter` = 结束休息（需长按/二次确认？默认单击即可）；`Esc` = 继续休息。
- 若用户解锁后 15 秒内没有操作，自动重新锁屏。

### 5.4 首次运行

- 一页式说明：工作时长、提醒点、休息锁屏、自动化不会被结束。
- 勾选“开机自动启动”（默认勾选）。
- 可选“立即开始一个测试周期”（2 分钟），方便验证提醒和锁屏。

- 30 秒提醒是默认开启的；如果只想要 30 秒、不要 60 秒，直接关掉 60 秒开关即可。
- 设置保存后立即写入配置，不需要重启程序。
- 历史窗口只读本地 JSONL，不上传网络。

## 6. GitHub 连接与开发管理

### 6.1 连接方式与账号凭据

**不需要把 GitHub 密码或 token 发到聊天里。** 采用 GitHub 官方设备码授权（OAuth Device Flow）：

1. 已下载并校验 GitHub CLI 官方 Windows x64 便携版 `v2.102.0` 到 `tools/gh/`（不提交到仓库）。
2. 我运行 `gh auth login --hostname github.com --git-protocol https --web --scopes "repo,workflow,read:user"`。
3. 终端显示一次性设备码（形如 `XXXX-XXXX`），并打开浏览器。
4. 你在浏览器里登录自己的 GitHub 账号，输入该设备码，点 **Authorize**。
5. 我这边只拿到一个存在 Windows 凭据管理器里的授权 token，不会看到你的密码；`gh auth status` 验证后即可建仓库、推送代码。
6. 仅在该仓库设置本地 Git 身份（不改全局）：
   - `user.name` = GitHub 显示名或 login
   - `user.email` = `<id>+<login>@users.noreply.github.com`

> 如果设备码流程在你的网络下打不开，备选方案是你在 GitHub 网页上创建一个 **fine-grained PAT**（只勾选目标仓库的 Contents/Issues/Pull requests 读写），然后在本机弹窗里粘贴；仍然不要发到聊天里。优先用设备码。

## 8. 测试计划

### 8.1 自动化测试（CI）

- 状态机：Idle→Working→Rest→Working、锁屏/睡眠清零、提醒只触发一次、配置边界。
- 计时：用可注入的 `IClock` 模拟 30 分钟，验证 29:00/29:30/0 的精确触发。
- 配置：默认值、非法值（0 分钟、负值、超过 180）、原子写入。
- 本地记录：正常周期、锁屏/睡眠结束原因、JSONL 追加与截断、CSV 导出字段。
- 注入过滤：把 `KBDLLHOOKSTRUCT.flags` 解析抽成纯函数，覆盖 injected / lower-IL injected / 正常输入。

### 8.2 真机手工回归

| 场景 | 步骤 | 期望 |
|---|---|---|
| 冷启动 | 重启 → 登录 → 按一次键盘 | 托盘出现，30:00 开始 |
| 提醒 | 设为 2 分钟，观察 1:00 / 0:30 | 各一次弹窗+声音，不重复 |
| 锁屏 | 等到 0 | 立即锁屏，托盘仍运行 |
| 防休眠 | Rest 中 `powercfg /requests` | 有本程序的 SYSTEM 请求；10 分钟不睡 |
| 自动化存活 | Rest 中查看自动化进程/日志 | PID 不变，后台任务继续 |
| 手动解除 | 解锁 → 点“结束休息” | 新的 30:00 开始 |
| 继续休息 | 解锁 → 点“继续休息” | 15 秒内重新锁屏 |
| 工作锁屏 | 10:00 时手动锁屏 → 解锁 | 显示待开始；按键后 30:00 |
| 睡眠恢复 | 10:00 时睡眠 → 唤醒 → 按键 | 显示待开始；按键后 30:00 |
| 自动输入 | PowerShell `SendInput` 循环 20 次 | 倒计时不启动 |
| 真人输入 | 物理键盘/鼠标 | 立即启动 |
| 单实例 | 重复双击 exe | 不出现第二个托盘图标 |
| 自启 | 重启登录 | 自动运行，无 UAC 弹窗 |
| 本地记录 | 完成一轮工作+休息 | `sessions.jsonl` 新增一条，历史窗口可见，CSV 可导出 |
| GUI 设置 | 改成 2 分钟、关闭 60s 提醒 | 下个周期 2 分钟，只在 30s 提醒 |

### 8.3 边界与异常

- 锁屏 API 被组策略禁用：记录错误并显示提示，不静默失败；`overlay` 兜底列入后续版本。
- 防休眠被电源策略覆盖：记录警告，提示检查 `powercfg /requests`。
- 系统时间被修改：单调计时不受影响。
- 多显示器/DPI 缩放：弹窗定位在主屏工作区，支持 125%/150%。
- 全屏游戏/会议：弹窗不抢焦点；锁屏仍按计划执行。
- 程序崩溃/被结束：重启后 Idle，不会突然锁屏；日志保留最后状态。

## 9. 风险与限制

1. **锁屏会阻断 GUI 自动化**。你已确认为后台任务，默认使用真正锁屏 `lock` 模式；如果以后自动化需要操作桌面窗口，可把自动化放到独立会话/服务中，`overlay` 模式列入后续版本。
2. **注入识别不是 100%**：`SendInput`/AutoHotkey/PyAutoGUI 会被过滤；硬件级 KVM、Arduino 模拟键鼠、部分驱动宏可能不带 injected 标志，无法与真人区分。
3. **需要管理员权限的场景**：UAC 安全桌面、登录界面、组策略限制下，普通进程收不到输入/不能锁屏；本工具不提升权限，遇到这些场景按“无操作”处理。
4. **防休眠不是永久的**：电源策略、系统更新、电池模式可能覆盖请求；Rest 期间会持续续期，但极端情况下仍可能睡眠。
5. **杀毒/EDR 误报**：全局钩子 + 自启可能被拦截；无代码签名时尤甚。需要你在安全软件里放行。
6. **GitHub 网络与额度**：当前网络可访问 github.com，但 api.github.com 未认证时出现过 403 rate limit；授权后会正常。公开仓库的 Actions 不消耗私有仓库分钟数。
7. **不提供医疗建议**：工具只执行计时与提醒，不判断身体状况；休息时长由你手动控制。
